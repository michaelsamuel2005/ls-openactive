# Spec — Incremental-validity check for the activity-gap index

**Status:** specified, not yet implemented. **Owner:** WS2 (Michael), with the
evaluation/validation lead (Fahmi). **Relates to:** D-012 (held-out validation).

## The question this answers
The held-out validation gives **Spearman(gap, inactivity) = +0.459** (non-City,
n=32). But because deprivation and demographics *themselves* predict inactivity,
a sceptical examiner asks the sharpest question the index faces:

> *"Is the activity-gap index anything more than deprivation relabelled?"*

The gap is `need − provision`. If its correlation with inactivity comes entirely
from the **need** side, the provision layer adds nothing and the index is just a
deprivation proxy. The incremental-validity check tests whether **provision adds
predictive signal for inactivity beyond need alone.**

## What we already know (bivariate, this session — non-City, Spearman)
| relationship | ρ |
|---|---|
| need_score_z vs inactivity | **+0.301** |
| provision_score_z vs inactivity | **−0.488** |
| gap_index_z vs inactivity | **+0.459** |

`gap` (0.459) already correlates with inactivity *more strongly than need alone*
(0.301), and provision is the more strongly-associated component — a **promising
but informal** hint that provision carries independent signal. This spec turns
that hint into a defensible result (or an honest null).

## Inputs (all already produced by the pipeline)
- `data/processed/borough_features.csv` — `pct_inactive_adults` (held-out outcome),
  `imd_avg_score`, the four demographic need columns, `sessions_per_10k`,
  `is_city_of_london`.
- `data/processed/borough_gap_index.csv` — `need_score_z`, `provision_score_z`,
  `gap_index_z`.
- **Analysis set:** the 32 non-City boroughs (City is excluded from scaling and
  has undefined provision — keep it out here too). n = 32.

## Method (two complementary tests; report both)
1. **Partial correlation.** Spearman **partial** correlation of
   `provision_score_z` with `pct_inactive_adults`, **controlling for
   `need_score_z`** (rank-based, robust at n=32). A non-zero partial ρ means
   provision predicts inactivity beyond need. Equivalently report partial
   Spearman(gap, inactivity | need).
2. **Nested models (incremental R²).**
   - **M1:** `inactivity ~ need_score_z`
   - **M2:** `inactivity ~ need_score_z + provision_score_z`
   - Report each model's adjusted R²; the **ΔR²** and an F-test / likelihood-ratio
     test for M2 vs M1; and the **provision coefficient** in M2 with its 95% CI.
   - Report the same for `gap_index_z` vs `need_score_z` as predictors, since
     `gap = need − provision` — an equivalent, more communicable framing.

## Decision rule (state it before running — no post-hoc goalposts)
- **Provision adds signal ("more than deprivation relabelled")** if, controlling
  for need, provision's association with inactivity is in the expected direction
  (more provision → less inactivity), its coefficient CI excludes 0, and ΔR² is
  material.
- **Honest null** if provision adds nothing beyond need. Report it plainly — a
  null here is a real, publishable finding ("the gap is need-aligned; the
  provision layer does not add measurable predictive value at borough scale,
  n=32"), not a failure to bury.

## Caveats to report with the result (non-negotiable)
- **Power.** n=32 is small: lead with effect sizes and CIs, not p-values alone;
  a null may be under-power, not absence of effect — say so.
- **Spatial autocorrelation.** Compute Moran's I on the model residuals (queen
  contiguity on the borough boundaries already loaded). If present, flag it and
  treat the OLS SEs as optimistic; a spatial-error model is the stretch follow-up.
- **Ecological / correlational.** Borough-level, observational — no causal or
  individual-level claim. Keep the CLAUDE.md no-accuracy / no-small-area locks.
- **Held-out integrity.** Inactivity must remain out of the need composite
  (D-012); this check reads it only as the outcome.

## Outputs
- `reports/incremental_validity.csv` (coefficients, CIs, adjusted R², ΔR²,
  partial ρ, Moran's I) — every number generated by the script (Rule Zero).
- One figure: need-vs-inactivity and gap-vs-inactivity scatter with borough labels.
- A dated **decision-log entry** recording the finding and which way it fell.

## Implementation sketch (~40–60 lines, no new heavy deps)
`statsmodels` OLS for the nested models; `pingouin.partial_corr` (or a manual
rank-residual Spearman) for the partial correlation; `libpysal` + `esda` for
Moran's I (or defer Moran's I to the stretch if adding pysal is unwanted). Scope
is one small script in `src/` + a results file — **not** a new modelling stage.
