# Prompt Playbook — Claude Code + Claude.ai for SEMTM0044

How to actually get reliable output, plus copy-paste prompts. Everything here
assumes CLAUDE.md is committed at the repo root and the Project instructions
are pasted into your claude.ai Project.

## 1. The working method (this matters more than any prompt)

**Explore → Plan → Code → Verify → Commit.** For anything non-trivial, put
Claude Code in plan mode first, read the plan, correct it, and only then let
it execute. Never accept a wall of code you haven't reviewed — you review
Claude's PRs exactly like a teammate's, because that IS your assessed
workflow (branch → PR → peer review → squash-merge).

**One task per session.** Start a fresh session (or `/clear`) for each new
task. Long, drifting sessions are where quality degrades and hallucination
creeps in. State the task, the acceptance criteria, and the definition of
done every time — cheap to paste, expensive to omit.

**Make it verify itself, then verify it yourself.** End every coding task
with: run the tests, print the sanity block (row counts, ranges, CRS,
% missing, duplicates), and state what remains UNVERIFIED. Then a human
eyeballs it. Claude checking Claude is useful; Claude checking Claude is
not sufficient.

**Say "think hard" on design decisions.** For choices like catchment sizes,
imputation strategy, or cluster count, ask for extended reasoning and 2–3
options with trade-offs — then the team decides and logs it in
`docs/decision-log.md`.

**Rules are guidance; enforcement is mechanical.** CLAUDE.md is context, not
a firewall. The things that must never happen should also be blocked
mechanically: GitHub branch protection on `main`, CI that runs pytest + ruff
on every PR (pandera when added), and Claude Code permission settings / hooks
to deny dangerous commands (force-push, `rm -rf`). If a rule failing would
break the project, don't rely on the rule alone. *(Status: a CI workflow
running pytest + ruff is now in `.github/workflows/ci.yml`; branch protection
on `main` still needs enabling in GitHub repo settings.)*

**Keep CLAUDE.md alive.** When Claude makes a mistake twice, that's a missing
rule — add it (use `/memory`, or just ask Claude to remember it). When a
decision is made (e.g. AREA_LEVEL = MSOA), update the "Project state"
section so every future session knows.

**Team hygiene.** Everyone works from the same committed CLAUDE.md; personal
preferences go in your own `~/.claude/CLAUDE.md`. Log notable AI-assisted
contributions in the decision log, consistent with the unit's AI-use rules
and what you learn in the Community & Integrity training — this also gives
each of you honest raw material for the reflective account.

> Review this diff as a strict teammate. Check against CLAUDE.md: CRS

## 3. Red flags — stop and check when Claude…
- states a number you didn't compute, or a field name you haven't seen in
  the actual data;
- cites a paper not in references.bib without a [LIT — VERIFY] flag;
- says a task is "done" without test output and the sanity block;
- makes a decision (unit of analysis, threshold, weight) instead of
  presenting options;
- produces text implying recommendation accuracy, small-area inactivity, or
  causality.
Any of these = the guardrails have slipped: fix the output, then add the
missing rule to CLAUDE.md so it doesn't recur.
